# Skill: test-design

## Purpose

Сформировать тестовую модель для Qase на основании требований, результатов `requirement-review` и проектов задач из `task-design`.

Skill отвечает только за тест-дизайн и не изменяет требования или Jira-задачи.

## Inputs

Обязательные:

- исходные требования;
- результат `requirement-review`;
- результат `task-design`;
- статус Quality Gates, позволяющий продолжение workflow.

Опциональные:

- правила оформления тест-кейсов;
- дополнительный технический контекст;
- сведения о ролях, состояниях, ограничениях и интеграциях.

## Procedure

1. Выделить тестируемые условия из требований и Acceptance Criteria.
2. Сформировать основной позитивный пользовательский сценарий.
3. Определить значимые альтернативные сценарии.
4. Определить негативные сценарии.
5. Применить классы эквивалентности, если они уместны.
6. Применить анализ граничных значений, если существуют числовые или иные границы.
7. Использовать таблицы решений, если результат зависит от комбинации условий.
8. Использовать переходы состояний, если функциональность содержит состояния и переходы.
9. Проверить роли и права, если поведение зависит от типа пользователя.
10. Сформировать тест-кейсы и связать их с требованиями и проектами Jira-задач.
11. Проверить покрытие требований, Acceptance Criteria, негативных и граничных сценариев.
12. Удалить явные дубли и необоснованные проверки.

## Rules

- Использовать только применимые техники тест-дизайна.
- Не генерировать проверки ради количества.
- Не придумывать бизнес-правила, которых нет во входных данных.
- Если ожидаемый результат неизвестен, зафиксировать вопрос вместо предположения.
- Каждый тест-кейс должен иметь понятную цель.
- Каждый тест-кейс должен быть трассируем к требованию и/или Acceptance Criteria.
- Не изменять требования.
- Не изменять проекты Jira-задач.

## Output

Для каждого тест-кейса:

### Test Case

- Test Case ID;
- Title;
- Source Requirement(s);
- Jira Draft;
- Type: `Positive`, `Negative`, `Boundary`, `Role`, `State`, `Decision`, `Other`;
- Preconditions;
- Steps;
- Expected Result.

### Coverage Summary

Показать:

- покрытие требований;
- покрытие Acceptance Criteria;
- наличие позитивных сценариев;
- наличие негативных сценариев;
- наличие граничных проверок, где применимо;
- роли и права, где применимо;
- состояния и переходы, где применимо;
- непокрытые элементы.

### Test Design Quality Gate Recommendation

Одно из значений:

- `PASSED`;
- `BLOCKED`.

Кратко объяснить причину.

## Completion Criteria

Skill выполнен успешно, если:

- покрыты основные требования и Acceptance Criteria;
- есть основной позитивный сценарий;
- добавлены существенные негативные сценарии;
- применимые границы проверены;
- роли, права, состояния и переходы учтены, если они существуют;
- нет очевидных дублей;
- все тест-кейсы трассируемы;
- дана обоснованная рекомендация по Test Design Quality Gate.
