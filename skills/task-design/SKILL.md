# Skill: task-design

## Purpose

Спроектировать проекты Jira-задач на основании проверенных требований и результатов `requirement-review`.

Skill не изменяет требования и не выполняет тест-дизайн.

## Inputs

Обязательные:

- исходные требования;
- результат `requirement-review`;
- статус Requirement Quality Gate, позволяющий продолжение workflow.

Опциональные:

- дополнительные ограничения;
- архитектурный или технический контекст;
- правила оформления Jira-задач, если они предоставлены.

## Procedure

1. Проанализировать требования, допущенные к дальнейшему проектированию.
2. Выделить независимые функциональные изменения или логические единицы работы.
3. Сгруппировать связанные требования в задачи без потери трассируемости.
4. Для каждой задачи сформировать понятное название.
5. Сформировать описание цели и ожидаемого изменения.
6. Сформировать Acceptance Criteria на основании требований.
7. Указать исходные требования, на которых основана задача.
8. Зафиксировать зависимости и открытые вопросы, если они известны.
9. Проверить, что все требования покрыты хотя бы одной задачей либо явно отмечены как не требующие отдельной задачи.
10. Проверить отсутствие необоснованного дублирования задач.

## Rules

- Не создавать задачу без основания во входных требованиях.
- Не придумывать отсутствующие бизнес-правила.
- Не изменять смысл требований.
- Не придумывать `Assignee`, `Sprint`, `Story Points`, `Deadline`, `Fix Version`, `Priority` и другие атрибуты, если они не были предоставлены.
- Если значение неизвестно, явно указать `Не определено`.
- Acceptance Criteria должны быть проверяемыми.
- Не создавать тест-кейсы.
- Не исправлять проблемы требований, скрытые в результате review.

## Output

Для каждой задачи:

### Task Draft

- Draft ID;
- Title;
- Source Requirements;
- Goal;
- Description;
- Acceptance Criteria;
- Dependencies;
- Constraints;
- Open Questions.

### Coverage

Таблица или список трассируемости:

- Requirement;
- Jira Draft;
- Coverage Status.

### Task Design Quality Gate Recommendation

Одно из значений:

- `PASSED`;
- `BLOCKED`.

Кратко объяснить причину.

## Completion Criteria

Skill выполнен успешно, если:

- все допущенные требования обработаны;
- проекты задач имеют явную связь с требованиями;
- Acceptance Criteria проверяемы;
- отсутствуют выдуманные проектные данные;
- непокрытые требования явно обозначены;
- дана обоснованная рекомендация по Task Design Quality Gate.
