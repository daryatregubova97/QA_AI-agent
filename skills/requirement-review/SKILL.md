# Skill: requirement-review

## Purpose

Провести независимый анализ требований и определить, достаточно ли они полны, однозначны, непротиворечивы и тестируемы для дальнейшего проектирования задач и тестов.

Skill решает только задачу review требований и не проектирует Jira-задачи и тест-кейсы.

## Inputs

Обязательные:

- текст требований или требования, полученные из Confluence.

Опциональные:

- бизнес-правила;
- связанная аналитика;
- ограничения;
- описание ролей и прав;
- дополнительный контекст, предоставленный пользователем.

## Procedure

1. Выделить отдельные требования и логические бизнес-правила.
2. Проверить требования на однозначность.
3. Проверить требования на полноту.
4. Найти внутренние противоречия.
5. Проверить тестируемость формулировок.
6. Найти отсутствующие предусловия, ограничения и ожидаемые результаты.
7. Проверить, определены ли роли и права там, где это влияет на поведение.
8. Проверить наличие значимых граничных условий, если они применимы.
9. Сформировать список проблем, рисков и вопросов на уточнение.
10. Определить, блокируют ли найденные проблемы дальнейшее проектирование.

## Rules

- Не изменять исходные требования.
- Не придумывать отсутствующие бизнес-правила.
- Не считать предположения фактами.
- Каждое замечание по возможности связывать с конкретным требованием или фрагментом входных данных.
- Разделять подтвержденные проблемы и вопросы на уточнение.
- Не создавать Jira-задачи.
- Не создавать тест-кейсы.
- Не выполнять действия вне задачи review требований.

## Output

### Summary

- количество проанализированных требований;
- количество найденных критических проблем;
- количество некритических замечаний;
- количество вопросов на уточнение;
- общий вывод о готовности требований.

### Findings

Для каждого замечания:

- Requirement / Source;
- Severity: `CRITICAL`, `MAJOR`, `MINOR`;
- Problem;
- Risk;
- Recommendation / Question.

### Missing Information

Список данных, которых не хватает для однозначного понимания требований.

### Requirement Quality Gate Recommendation

Одно из значений:

- `PASSED`;
- `BLOCKED`.

Кратко объяснить причину.

## Completion Criteria

Skill выполнен успешно, если:

- все предоставленные требования проанализированы;
- найденные противоречия и неоднозначности зафиксированы;
- критичные пробелы в полноте обозначены;
- сформированы вопросы на уточнение;
- не добавлены придуманные требования;
- дана обоснованная рекомендация по Requirement Quality Gate.
