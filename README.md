# QAI-07 · QA Agent Design

Проектирование QA-агента для последовательной работы с требованиями: от анализа качества требований до формирования Jira-задач и тестовой модели для Qase.

## Workflow

```text
Confluence / Requirements
        ↓
requirement-review
        ↓
Requirement Quality Gate
        ↓
task-design
        ↓
Task Design Quality Gate
        ↓
test-design
        ↓
Test Design Quality Gate
        ↓
Final Result
```

Если на одном из этапов обнаруживается критическая проблема, агент не продолжает зависимый workflow и передаёт проблему на уточнение.

## Agent Instruction

`agent_instruction.md` определяет постоянные правила работы QA-агента:

- Role и Responsibility
- Scope
- Inputs
- Workflow
- Tools
- Constraints
- Output
- Quality Gates
- Failure Behaviour
- Escalation Rules

Agent Instruction отвечает за общую оркестрацию процесса и не дублирует методики отдельных Skills.

## Skills

### requirement-review

Анализирует требования перед дальнейшим проектированием.

Проверяет:

- полноту
- однозначность
- непротиворечивость
- тестируемость
- роли и права
- ограничения
- недостающую информацию

Результат Skill - review требований, найденные проблемы и рекомендация по прохождению Requirement Quality Gate.

### task-design

Проектирует Jira-задачи на основании требований, прошедших review.

Формирует:

- название задачи
- цель и описание
- Acceptance Criteria
- связь с исходными требованиями
- зависимости
- открытые вопросы

Skill не придумывает отсутствующие проектные данные и сохраняет трассируемость к исходным требованиям.

### test-design

Формирует тестовую модель для Qase.

В зависимости от функциональности могут использоваться:

- позитивные сценарии
- негативные сценарии
- классы эквивалентности
- анализ граничных значений
- таблицы решений
- переходы состояний
- проверки ролей и прав

Каждый тест-кейс должен быть связан с исходным требованием и/или Acceptance Criteria.

## Quality Gates

Quality Gates используются между этапами workflow и не позволяют передавать дальше результат недостаточного качества.

Проверяется:

- достаточно ли требований для дальнейшей работы
- отсутствуют ли критические противоречия
- покрывают ли Jira-задачи исходные требования
- являются ли Acceptance Criteria проверяемыми
- покрывает ли тестовая модель основные требования и значимые сценарии
- отсутствуют ли необоснованные предположения

Если Quality Gate получает статус `BLOCKED`, агент останавливает зависимый этап и запрашивает уточнение.

## Key Principles

- не придумывать отсутствующую информацию
- не изменять исходные требования
- не считать предположение подтверждённым фактом
- использовать только релевантные Skills и Tools
- сохранять трассируемость между требованиями, Jira-задачами и тестами
- эскалировать критические неопределённости человеку
